# 捜索状況共有アプリ（Cloudflare Workers + D1版） v2.7

災害時に救助隊が「どの建物を捜索したか」を地図上で共有するWebアプリです。
Cloudflare上で24時間動くので、PCを起動しておく必要はありません。

## 主な機能

- アカウント登録・ログイン・ログアウト（ログインは30日間有効、再デプロイしてもログアウトされない）
- ピンの設置：**現在地（GPS）／地図をタップ／住所で検索** の3通り
  - 新しいピンには住所が自動入力される（座標 → 住所）
- **重複捜索の警告**：30m以内に既存のピンがあると、設置時に警告と既存ピンへのリンクを表示
- ピンの項目（INSARAG準拠）：建物名・階・住所・状況（未捜索／捜索中／捜索済み）・進入（GO／NO GO）・
  行方不明M／生存L／死亡D・危険情報・**捜索開始／終了時刻**・メモ
  - 状況を「捜索中」にすると開始時刻、「済」にすると終了時刻が自動入力される（空欄の場合のみ）
- **作成者・最終更新者と更新時刻**をピンごとに表示
- **10秒ごとの自動更新**：他の隊の変更がリロードなしで反映される（編集中のピンが他の人に更新されたら通知）
- **オフライン対応**：通信が切れても保存したピンは端末に保持され、接続が戻ると自動送信。
  画面左上に「同期 10:12」「オフライン」「未送信 N件」を表示
- **隊で絞り込み**（全隊／自隊／各隊）
- **各隊の位置を地図に表示**：各隊のスマホ・タブレットのGPSを定期的に送り、他の隊の位置を地図に表示。**位置の古さ（「たった今」「5分前」など）**も一緒に出し、10分以上更新がない位置は「！」と薄い表示で目立たせる
- **近い隊（応援の候補）**：ピンの編集画面に、その現場に近い隊を距離の近い順に最大3隊表示（ピンを作成した隊は除く）
- **状況マークで絞り込み**：画面左上の赤・緑・灰のマークを押すと、その状況のピンだけを地図に表示（複数選択可、「全て表示」で解除）
- **未捜索（赤）ピンの強調表示**：太い枠とパルス表示で、地図上で目立つようにする
- **編集中のピン切り替え**：編集画面を開いたまま別のピンを押すと、すぐにそのピンの編集画面に切り替わる
- **未保存の変更の警告**：入力内容を変更したまま閉じる・別のピンへ移動しようとすると確認を表示（一覧を開くだけなら警告なし）
- **人数は直接入力も可能**（−10／−1／＋1／＋10ボタンも使える。建物全体・階・店舗のすべての入力欄）
- **建物の人数（合計）**：編集画面の建物名の横に、建物全体の M＋L＋D の合計と内訳を表示（階・店舗があればその合計。入力するとすぐ更新）
- **日本語／English 切り替え**
- **要救助者（V）マーク**（INSARAG準拠）：建物ごとに、要救助者がいる地点を地図に記録。状況は「V 可能性あり／L 生存確認／D 死亡確認／救出済み」
- **建物の写真**：ピンに写真を添付（マーキングや被害状況の記録）。端末で自動的に縮小してから送信
- **オフラインでも起動（PWA）**：ホーム画面に追加してアプリのように使える。圏外でも前回同期したピン・Vと、一度表示した範囲の地図が見られる
- **事前確認用の施設**：学校（学）・工場（工）・発電所／変電所（電）・大型商業施設（商）を地図に自動で表示。種類ごとに表示を切り替えられ、施設を押すと「この場所にピンを設置」で名前入りのピンをすぐ作れる
- 背景地図の切り替え：OpenStreetMap／地理院地図／地理院 淡色／航空写真
- 昼／夜テーマ、QRコードでURL共有

- **本部と隊員の区別（種類だけ）**：登録のときに「隊員として登録」「本部として登録」を選べる。本部として登録するには、サーバーに設定した**本部用の合言葉**が必要。**今のところ、権限の違いはない**（ピン・階・店舗・区画の追加や削除は、現場の隊員もできる）
- **かんたん操作**：既存のピンを開くと、大きな「未捜索／捜索中／捜索済み」ボタンが出て、押した時点で保存される。詳しい入力は「詳しく入力」を開くと、これまで通り使える（開閉は端末に記憶される）
- **階数・店舗・区画ごとの入力**：建物・住所の下の「階数」で、「階数なし」（これまで通り）か「階数を入力」（地上○階・地下○階 → 階ごとの閉じたタブができる）を選ぶ。階の中に店舗・区画を追加すると、状況〜メモは店舗・区画の中で入力する。階の状況は店舗・区画から自動で決まり（捜索中が1つでもあれば捜索中。全部が同じ状況のときだけ、未捜索・捜索済み。未捜索と捜索済みが混ざっているときは捜索中）、人数は合計が表示される。建物のピンの状況・人数・危険情報・時刻も、階から自動で決まり、ピンには「捜索済みの階／階の数」が出る

## 各隊の位置共有について

- 画面左上の「位置共有：ON/OFF」で、自分の位置を送るかどうかを切り替えられる（初期状態はON）。OFFにすると、サーバーから自分の位置が消える
- 「隊の位置：表示/非表示」で、他の隊のマーカーを地図に出すか選べる
- 位置は動いたとき（20m以上、15秒おき）と、止まっていても60秒おきに送る
- **スマホの画面を消す・アプリを裏に回すと、ブラウザが位置の更新を止める**（端末の仕様）。そのため位置の古さを表示している。復帰するとすぐ送り直す
- 3時間以上更新がない位置は自動で消える。ログアウトしたときも消える
- 初回のみ、ブラウザの位置情報の許可が必要

## 要救助者（V）・写真について

- ピンの編集画面の下にある「要救助者（V）」「写真」から追加する（ピンを一度保存してから。かんたん操作の画面にも表示される）
- Vの位置は「建物の位置／現在地／地図で指定」から選べる。地図上では赤い **V**（可能性あり）・**L**（生存確認）、**D**（死亡確認）、斜線入りの **V**（救出済み）で表示
- Vの状況は他の隊も更新できる（救出した隊が「救出済み」にするなど）。削除できるのは追加した隊のみ
- 写真は長辺1600px・約0.9MB以下に縮小してからD1に保存（1枚最大1MB）。削除できるのは撮影した隊のみ
- **階ごとの写真**：階数を入力した建物では、各階のタブの中の「この階の写真」から、その階の写真を追加できる。建物全体の「写真」欄には、階のない写真と、削除された階の写真が表示される
- ピンを削除すると、その建物のVと写真も一緒に削除される
- 要救助者・写真の追加はオンライン時のみ（ピンの追加・編集はオフラインでも保存され、後で自動送信）
- 写真を大量に保存する運用になったら、Cloudflare R2（画像用ストレージ）への移行を検討

## 事前確認用の施設について

- 画面左上の「施設：すべて／学校／工場／発電所／商業施設／非表示」で切り替える（選択は端末に保存）
- 地図をある程度拡大したとき（縮尺 約300m以下）に表示される。縮小しているときは表示しない（数が多くなりすぎるため）
- データは [OpenStreetMap](https://www.openstreetmap.org/copyright) から Overpass API で取得（無料・APIキー不要）。サーバー側で約2.4km四方ごとに7日間キャッシュし、端末にも保存するので、一度表示した地域は圏外でも見られる
- 対象：
  - 学校：小中高校・幼稚園／保育園・大学・専門学校（`amenity=school/kindergarten/university/college`）
  - 工場：工場（`man_made=works`）、名前のある工業地域・工場の建物
  - 発電所・変電所：発電所（`power=plant`）、名前のある変電所
  - 大型商業施設：ショッピングモール・百貨店（`shop=mall/department_store`）、名前のある商業ビル（`building=retail`）
- OpenStreetMap に登録されていない施設は表示されない（地域によって登録の多さに差がある）。必要な施設は、通常のピンとして置いておく
- 画面右下の「施設データ © OpenStreetMap」の表示は利用規約上必要なので消さないこと

## アプリとしてインストール（PWA）

- **Android（Chrome）**：メニュー（︙）→「アプリをインストール」または「ホーム画面に追加」
- **iPhone（Safari）**：共有ボタン →「ホーム画面に追加」
- 一度オンラインで開いてログインしておくと、圏外でもアプリが起動し、前回同期したデータが表示される
- 地図タイルは表示した範囲だけ端末に保存される（最大約1500枚）。現場に入る前に、担当エリアを一通り拡大して表示しておくと圏外でも地図が出る
- アプリを更新したら `public/sw.js` の `VERSION` を上げる（古いキャッシュが消え、新しい版に切り替わる）

## 必要なもの

- Node.js 20以降：https://nodejs.org/
- Cloudflareアカウント（無料）

## 初回デプロイ

このフォルダでターミナルを開いて、上から順に実行します。

```bash
# 1. 必要なツール(wrangler)をインストール
npm install

# 2. Cloudflareにログイン（ブラウザが開く）
npx wrangler login

# 3. データベースを作成
npx wrangler d1 create search-share-db
```

3で表示された `database_id = "xxxxxxxx-...."` を、`wrangler.jsonc` の
`REPLACE_WITH_YOUR_DATABASE_ID` の部分に貼り付けて保存します。

```bash
# 4. テーブルを作成（migrations/ のSQLを順番に適用）
npm run db:migrate

# 5. 本部用の合言葉を設定（本部として登録できる人を限るため。聞かれたら合言葉を入力）
npx wrangler secret put HQ_CODE

# 6. デプロイ
npm run deploy
```

> 合言葉は、班で決めて、本部の担当者だけに伝えてください。`HQ_CODE` を設定しないと、本部として登録できません（隊員としてだけ登録できます）。
> 合言葉の入力回数には制限をかけていません。推測されにくい長さ・文字列にしてください。

最後に `https://search-share.<あなたのサブドメイン>.workers.dev` というURLが表示されれば完了です。
HTTPSなので、スマホのGPS（現在地取得）もそのまま使えます。

## 更新するとき

```bash
npm run db:migrate   # migrations/ に新しいファイルが増えたときだけ（何度実行しても安全）
npm run deploy
```

データはそのまま残ります。

> **v2.5 に更新するとき：** `npm run db:migrate`（0004: 要救助者・写真、0005: アカウントの種類、0006: 階・店舗の列を追加）→
> `npx wrangler secret put HQ_CODE` → `npm run deploy` の順に実行します。これまでのアカウントはすべて「隊員」になります。
> 既存のアカウントを本部にしたいときは、次のコマンドを実行します（`ID` を書き換える）:
> `npx wrangler d1 execute search-share-db --remote --command "UPDATE users SET role='hq' WHERE id='ID'"`
>
> v1（住所・階・メモ・時刻なし）を既にデプロイ済みの場合も、`npm run db:migrate` → `npm run deploy` でOK。
> v1を `schema.sql` で作った場合、0001は `IF NOT EXISTS` なので問題なく、0002で列が追加されます。

## GitHubから自動デプロイしている場合（Workers Builds）

自動デプロイ用のトークンにはD1の権限がないため、**テーブルの追加・変更はCloudflareのダッシュボードで手動で行います**。

1. Storage & Databases → D1 → `search-share-db` → **Console**
2. `migrations/` の中で、まだ実行していないSQLファイルの中身を貼り付けて実行（番号順）
   - v2.2：`0003_positions.sql`（各隊の位置）
   - v2.4：`0004_victims_photos.sql`（要救助者・写真）
   - v2.5：`0005_roles.sql`（アカウントの種類）、`0006_floors.sql`（階・店舗・区画）
   - v2.6：`0007_photo_floor.sql`（写真を階ごとに分ける）
3. 本部用の合言葉：Workers & Pages → `search-share` → Settings → **Variables and Secrets** → Add → 種類「Secret」、名前 `HQ_CODE`、値に合言葉
4. その後に GitHub へ push する（`wrangler.jsonc` の `database_id` は自分のものを残すこと）

この方法で運用する場合は `npm run db:migrate` を混ぜて使わないこと（同じSQLを二重に実行しようとしてエラーになる）。

> 注意：チームのv2.3.1では `0004_roles.sql`・`0005_floors.sql` という名前だったが、v2.4の `0004_victims_photos.sql` と番号が重なるため、
> v2.5で `0005_roles.sql`・`0006_floors.sql` に変更した（中身は同じ）。

## 自分のドメインで公開したい場合

Cloudflareのダッシュボード → Workers & Pages → `search-share` → Settings → Domains & Routes → Add → Custom domain
で、例えば `search.example.com` のようなサブドメインを設定できます。

## 権限のルール

- ピンの追加・編集：ログインしていれば誰でも可（他の隊が捜索状況を更新できるように）
  - ただし「作成した隊」「作成者」は変更できない。最後に更新した人と時刻が記録・表示される
- ピンの削除：**そのピンを作成した隊のメンバーのみ**（他の隊のピンには削除ボタンが表示されず、サーバー側でも拒否する）。土砂や津波で建物が動いたときなど、現場の隊員が自分たちでピンを置き直せる
  - 階・店舗・区画の追加・更新・削除は、現場の隊員もできる（ピンを作った隊に限らない）
- 本部アカウントは、登録のときに本部用の合言葉（`HQ_CODE`）を入力した人だけ
- 同じピンを複数の人が同時に編集すると、あとから保存した内容で上書きされる（編集中に他の人が更新したときは、画面に通知が出る）。同じ建物の別々の店舗を同時に更新すると、先に保存した人の変更が消えることがある
- 要救助者（V）：追加・状況の更新は誰でも可、削除は追加した隊のみ。写真：追加は誰でも可、削除は撮影した隊のみ
- 住所検索APIもログイン必須（外部からの乱用防止）

## 住所検索について

住所 ⇄ 座標の変換は [OpenStreetMap Nominatim](https://nominatim.org/) を Worker 経由で使っています（無料・APIキー不要）。
利用規約で「1秒に1回程度まで」とされているため、結果は1日キャッシュしています。
学内発表・デモの規模なら問題ありませんが、大人数で常時使う場合は有料の地図APIへの切り替えを検討してください。

## データの確認・削除

```bash
npx wrangler d1 execute search-share-db --remote --command "SELECT id, team FROM users"
npx wrangler d1 execute search-share-db --remote --command "SELECT id, name, status, team, created_by FROM pins"
npx wrangler d1 execute search-share-db --remote --command "DELETE FROM pins"   # ピンを全部消す
```

Cloudflareのダッシュボード（Storage & Databases → D1）からも中身を見られます。

## ファイル構成

```
src/index.js         サーバー本体（Cloudflare Worker）
migrations/          データベースのテーブル定義（順番に適用される）
wrangler.jsonc       Cloudflareの設定
public/index.html    アプリ本体（フロントエンド）
public/sw.js         service worker（オフライン起動・地図の保存）
public/manifest.json PWAの設定（アプリ名・アイコン）
public/icons/        アプリのアイコン
public/vendor/       Leaflet 1.9.4・qrcodejs（外部CDNに依存しないよう同梱）
```

## 地図について

背景地図は画面左上のメニューで切り替えられます（選択は端末に保存されます）。

| 種類 | 提供元 | 備考 |
|---|---|---|
| OSM | [OpenStreetMap](https://www.openstreetmap.org/copyright) | 世界中で使える |
| 地理院地図 / 地理院 淡色 | [国土地理院 地理院タイル](https://maps.gsi.go.jp/development/ichiran.html) | 日本の公式地図。建物の形まで詳しい |
| 航空写真 | 国土地理院（全国最新写真・シームレス） | 建物の屋根・倒壊状況の確認に便利 |

どれも無料・APIキー不要です。地図は [Leaflet](https://leafletjs.com/) で表示しています。
画面右下の出典表示（OpenStreetMap／国土地理院）は利用規約上必要なので消さないでください。
国土地理院の地図は日本国内のみです。
